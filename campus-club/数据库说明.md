# 校园社团成果展示与孵化系统 - 数据库说明

## 数据库数量

本项目使用 **1个数据库**，采用 MySQL 作为数据库管理系统。

## 数据库设计

### 数据库名称
- **数据库名**：`campus_club`

### 核心数据表

#### 1. 用户表 (`user`)
- **功能**：存储用户基本信息
- **关键字段**：
  - `id` (主键)
  - `username` (用户名)
  - `password` (密码，加密存储)
  - `user_type` (用户类型：student/teacher/admin)
  - `college` (学院)
  - `create_time` (创建时间)

#### 2. 学生表 (`student`)
- **功能**：存储学生详细信息
- **关键字段**：
  - `id` (主键)
  - `user_id` (外键，关联用户表)
  - `student_id` (学号)
  - `name` (姓名)
  - `major` (专业)

#### 3. 教师表 (`teacher`)
- **功能**：存储教师详细信息
- **关键字段**：
  - `id` (主键)
  - `user_id` (外键，关联用户表)
  - `teacher_id` (工号)
  - `name` (姓名)
  - `department` (部门)

#### 4. 成果表 (`achievement`)
- **功能**：存储社团成果信息
- **关键字段**：
  - `id` (主键)
  - `title` (成果标题)
  - `description` (成果描述)
  - `type` (成果类型)
  - `cover` (封面图片)
  - `student_id` (外键，关联学生表)
  - `create_time` (创建时间)
  - `score` (评分)
  - `incubation_status` (孵化状态)

#### 5. 孵化表 (`incubation`)
- **功能**：存储成果孵化信息
- **关键字段**：
  - `id` (主键)
  - `achievement_id` (外键，关联成果表)
  - `status` (孵化状态)
  - `progress` (孵化进度)
  - `start_time` (开始时间)
  - `end_time` (结束时间)

#### 6. 资源表 (`resource`)
- **功能**：存储可对接的资源信息
- **关键字段**：
  - `id` (主键)
  - `name` (资源名称)
  - `type` (资源类型)
  - `description` (资源描述)
  - `provider` (提供者)
  - `create_time` (创建时间)

#### 7. 申请表格 (`application`)
- **功能**：存储资源申请信息
- **关键字段**：
  - `id` (主键)
  - `student_id` (外键，关联学生表)
  - `resource_id` (外键，关联资源表)
  - `status` (申请状态)
  - `apply_time` (申请时间)
  - `reason` (申请理由)

#### 8. 通知表 (`notification`)
- **功能**：存储系统通知信息
- **关键字段**：
  - `id` (主键)
  - `title` (通知标题)
  - `content` (通知内容)
  - `type` (通知类型)
  - `create_time` (创建时间)
  - `is_read` (是否已读)

## 数据库关系

- **用户表** 与 **学生表/教师表**：一对一关系，通过 `user_id` 关联
- **学生表** 与 **成果表**：一对多关系，一个学生可以有多个成果
- **成果表** 与 **孵化表**：一对一关系，一个成果对应一个孵化记录
- **学生表** 与 **申请表格**：一对多关系，一个学生可以提交多个申请
- **资源表** 与 **申请表格**：一对多关系，一个资源可以被多个学生申请

## 数据存储方式

- **用户密码**：使用 BCrypt 加密存储
- **图片资源**：存储图片路径，实际图片保存在服务器文件系统中
- **时间戳**：使用 MySQL 的 `DATETIME` 类型存储

## 数据库优化

1. **索引优化**：为常用查询字段（如 `user_id`、`achievement_id` 等）创建索引
2. **分表策略**：对于数据量较大的表（如成果表、通知表），考虑使用分表策略
3. **缓存机制**：使用 Redis 缓存热点数据，提高查询速度
4. **事务管理**：关键操作（如成果提交、资源申请）使用事务保证数据一致性

## 总结

本项目使用单一 MySQL 数据库，通过合理的表结构设计和关系管理，实现了用户管理、成果管理、孵化管理、资源对接和通知系统等核心功能。数据库设计考虑了系统的扩展性和性能需求，为系统的稳定运行提供了可靠的数据基础。
